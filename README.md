<summary><b>📂 CASE #001 — HOTEL+</b> &nbsp;🏨 <i>Hotel Booking Management System</i></summary>

<br>

**<b>Classification:</b> Full-stack hotel booking web application**

**<b>Mission brief:</b> HOTEL+ is a cinematic hotel booking experience for a fictional Cebu City hotel, combining a polished marketing website, room catalog, complete reservation flow, authentication, booking confirmation, and a protected admin dashboard.

**<b>Core features:</b>

* 🏨 Cinematic hotel marketing homepage
* 🔎 Quick-search booking interface
* 🛏️ Standard, Deluxe, and Suite room catalog
* 📋 Detailed room information
* 📅 Complete reservation flow
* 👤 Guest checkout without an account
* 🔐 Supabase authentication and registration
* 🧾 Unique booking references
* ✅ Booking confirmation page
* 📖 Registered users can view their own bookings
* 🖥️ Protected admin dashboard
* 📊 Live booking statistics
* 🔎 Searchable and filterable reservations
* 💳 Booking and payment breakdown
* ✏️ Booking cancellation/update actions
* 📥 CSV reservation export
* 🗄️ PostgreSQL database through Supabase
* 🔒 Row Level Security for access control
* ✨ GSAP + Lenis animations
* 📱 Responsive desktop and mobile interface

**<b>Tech stack:</b>

`HTML` `CSS` `JavaScript` `Supabase` `PostgreSQL` `GSAP` `Lenis`

**<b>Architecture:</b>

Static front-end application with no build step or custom server. The browser communicates directly with Supabase through the `supabase-js` CDN client for authentication and database operations.

**<b>Database:</b>

* `auth.users` — Supabase-managed authentication accounts
* `profiles` — user profiles and admin access flag
* `rooms` — Standard, Deluxe, and Suite room data
* `bookings` — reservation records and booking information

**<b>Security:</b>

Row Level Security policies control database access. Guests can browse rooms and create bookings, signed-in users can access their own bookings, and authorized administrators can manage reservations through the protected dashboard.

**<b>What I built:</b>

Designed and developed the complete HOTEL+ experience, including the responsive UI, room catalog, reservation flow, authentication integration, booking logic, Supabase database integration, confirmation system, and admin dashboard.

<summary><b>📂 CASE #004 — QuestGo</b> &nbsp;🚧 <i>In development</i></summary>

<br>

**<b>Classification:</b> Hyperlocal student-to-student errand marketplace for CIT-U**

**<b>Mission brief:</b> QuestGo connects CIT-U students who need small tasks completed with fellow students willing to complete them for payment at approved campus meet-up points.

**<b>How it works:</b>

*Requesters* post **Quests**, while *Runners* accept and complete them for cash.

**<b>Built-in safeguards:</b>

* 🔐 Verified student accounts through CIT-U email
* 🔒 Quest details locked after acceptance
* ✅ Mutual, staged completion confirmation
* 🚫 Cancellation tracking with restrictions after repeated cancellations
* 📍 Approved campus meet-up locations only

**<b>Interesting problem solved:</b>

Ensuring that only **one Runner can accept a Quest**, with the acceptance constraint handled at the database level.
